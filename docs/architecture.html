Bakeoff

Private chat, from first principles

One person, one device. A message goes in, a reply comes back, and the transcript stays on that device. Everything else is optional.

The three pieces

1. ConversationWhat you type and what you read. It does not compute the reply.
→
2. MemoryThe transcript, saved on this device before and after the reply.
→
3. ModelTurns the recent transcript into the next sentence. Runs on this device.
The wall. The sentence crosses from the conversation to the model inside the device. It is not posted to a chat service. Loading the app (HTML, or later the App Store binary) is a download. The chat is not part of that download.

One turn

WriteSave your message locally first, so a crash does not lose it.
→
InferHand the recent turns to the on-device model. No network call.
→
WriteSave the reply in the same local store.

If inference fails, the transcript still shows your message and an error. The app does not quietly send the text somewhere else to get an answer.

Where the model can sit

In the appWeights and runtime live in the process (browser worker, or on iOS a native runtime). This is the shape to explain and to ship. Kiln did this with a tiny model in the tab.
Beside the appThe app asks a program on the same machine (Ollama on loopback). Still designed this as an optional path and refused to pretend it had been run. A phone does not have that side process unless the app itself contains the runtime.

What each bakeoff actually argued

Still (Codex, GPT-6 Astra) is the document to learn from. It separates “a reply” from “a language model,” draws the wall (what is stored, what a request is allowed to be, what happens when saving fails), and says the real local model was not exercised here.

Kiln (Grok 4.7) is the proof that weights can run in the client: a 77M model, ONNX, WebAssembly, history in IndexedDB. The writeup mostly describes that page. The model is too small to be the product idea, and the weights arrive as part of the site download, then stay in the browser cache. They were not already on your Mac.

What we are not building yet

  • Accounts, sync, or a copy of the chat in the cloud.
  • Voice, images, plugins, or a catalog of models.
  • System One models (Laya, OpenJev, Kev). Those pick or score. They do not write the reply. They can sit in front later, as a fast local decision, not as the chat model.

Next step is a native iOS shell of this same picture: conversation, on-device memory, on-device model. That path is the TestFlight runbook.
